# 方法论

把"从截图找种子"拆成五个可控的环节. 每个环节都可能出错, 而错误的代价是几十分钟的全空间扫描,
所以每个环节都要有独立的验证手段.

## 一. 观测: 用什么图

**只能用游戏主画面, 不能用地图.**

地图截图看似信息量大 (能一屏看到半个世界), 但它是**玩家后期改过地形**的结果: 挖过矿, 建过房,
填过坑. 它反映的不是世界生成的结果, 因此原理上不可能与模拟剖面吻合.

主画面也有代价: 一屏只有大约 100 格, 且被树木遮挡. 但它是**刚进游戏时的地表原貌**, 与生成结果一致.

补充数据的方式是**沿地面走一段距离, 连续截多张**, 相邻两张保留半屏重叠, 再用重叠区拼成一条长剖面.
列数决定了判据的分辨力: 74 列时假候选带在 0.95, 126 列时降到 0.89, 249 列 (含手工标注) 时降到 0.61.

## 二. 提取: 从像素到剖面

对图像每一列自上而下找第一个"暖色"像素 (红减蓝大于 8 且绿减蓝大于 4), 作为地表.

两个必须处理的干扰:

- **树冠**. 亮绿色叶子的 红减蓝 也能超过 8, 会被当成地表. 判断规则是"向下连续 10 格都是暖色
  且再往下 15 格内不出现天空间隙", 后者用来区分树冠 (下面有树干两侧的缝隙) 与真实地面 (下面是厚土层).
  宽树冠横跨多列且厚度超过 10 格, 靠"比邻居高一格"的离群剔除抓不到, 必须靠间隙判据.
- **玩家角色**. 站在地表上会挡住那一列, 直接剔除该列即可.

## 三. 定标: 这一步最致命

需要求出三个量: 每格的像素宽, 网格相位 (格子边界落在图像的哪个位置), 以及出生点在剖面里的列号.

**不要用"地表高度必为整数"来自动定标.** 这条判据看起来天经地义, 但在一段近乎平坦的地形上,
任何格宽都能让剖面"接近整数" (常数序列天然满足), 于是它退化成"取最平滑的那个采样", 会系统性偏大.
本项目的实际教训是: 它给出 21.25 到 22.25, 而真值是 20.86, 偏差 10 到 15 个百分点.
后果是整份观测被横向拉伸, 真种子永远对不上, 而拉伸后的平滑剖面反而极容易被大量假种子匹配 ——
表现为"全空间扫完却没有任何高分离群".

**可靠的定标方式是直接量画面里的方块.** 让用户在游戏里框出一个 2x2 方块, 得到像素尺寸,
再除以 2 就是格宽. 相位由那个框的左上角给出.

**自检指标是台阶率.** 真实地形在出生点附近的相邻格跳变比例约 9 到 15 个百分点.
用 21.25 提取时这个数字是 **0.0 个百分点** (一条假地平线), 换成 20.86 后恢复到 9 个百分点量级.
提前看这个数, 比事后分析候选分数分布有效得多.

## 四. 判据: 怎么算"像"

把观测与模拟剖面按列对齐, 残差超过半格的列判为不命中, 命中率即分数.

- **纵向偏移**用残差中位数消掉, 不参与搜索 —— 世界坐标的绝对高度没有意义, 只有相对起伏有意义.
- **精度要在两侧对齐.** 模拟高度是小数, 而观测若是整数 (写文件时用了 `%.0f`), 完全对齐时残差
  仍是 `[0,1)` 的均匀抖动, 只有一半能过 0.5 容差, 真种子满分会被压到 0.84. 两侧统一量化到 1/8 格即可.
- **横向偏移与比例尺一起搜.** 比例尺不确定度来自定标, 早期曾低估到正负 3 个百分点, 漏掉真值.

判定门槛必须用**已知种子**校准: 造一份同格式观测, 跑同样的搜索, 记录真种子得分与假候选上限.
本项目的对照数据 (249 列) 是: 真种子 1.0000, 假候选上限 0.6145.

## 五. 搜索: GPU 双内核

CPU 版每换一个偏移就要重跑全部模拟, 代价随 `偏移数 x 比例尺数` 线性增长.
GPU 版把这件事拆成两步:

- **内核 A**: 一个线程负责一个种子, 解析种子后模拟出所需的列窗口, 整段写进全局内存. 每个种子只算一次.
- **内核 B**: 一个 block 负责一个种子, 把窗口装进共享内存, 让 256 个线程并行评估
  `偏移数 x 比例尺数` 个组合, 用直方图求中位数, 命中数用 `atomicMax` 归并.

实测两块 4090 各约 80 到 110 万种子每秒, 全空间约 40 分钟. 同一空间用 CPU 版本要按天算 ——
这也是"该不该上 GPU"这个问题的答案.

几个实现上的坑:

- 内核 B 里曾写死"有效列数不足 200 就跳过", 而主画面观测只有 74 列有效, 导致**所有组合被跳过,
  候选恒为 0**. 候选数为 0 不等于判据锐利, 要先怀疑内核压根没打分.
- 结果收集不能按"发现顺序"取前 N 条. 假候选会瞬间打满上限, 之后出现的高分种子被丢弃.
  改成每批只保留分数最高的若干条.
- 两块卡并行时若工作目录相同, 输出文件会互相覆盖, 必须各自独立目录.

## 六. 参数传递: 一个反复出现的事故

内核的 `--spawn-lo` / `--spawn-hi` 是**出生点的世界列**, 代码内部自行减去 marker 得到观测第 0 列
对应的世界列. 曾经误传了已经减过 marker 的值, 使搜索整体错位 141 列.

这种错误**不会报错**, 只会表现为"扫完了, 榜首 0.93, 每批打满, 但没有明显断层".
识别方法是看日志里的窗口范围: 正确的窗口起点应当是 `spawn-lo - marker`.
更根本的办法是**先跑已知种子的对照** —— 如果真种子在自己的观测上都拿不到满分, 那一定是配置错了,
而不是"判据不够强".

**出生点列本身不是自由参数.** 世界中心的 0.48W 到 0.52W 被强制成平坦平台, 液体与
`worldSurface` 两个扩大条件都不会触发, 所以出生点恒为 `maxTilesX / 2 + genRand.Next(-5, 5)`,
中世界即 3200 加减 5. 工作台因此直接按这个规则推导窗口, 再叠 64 列容差吸收标注偏差
(中世界 3131 到 3269), 界面上不再出现这两个输入.

容差取 64 的依据: 一次真实观测里标注列与出生点差了 38 列, 用旧的 3180..3220 时真种子只得 0.082,
195 个有效列各自错开 18 列, 直方图整段落在正负两格之外; 换成按规则推导的窗口后真种子回到 1.0000.
放宽窗口可以覆盖更大的标注误差, 代价线性增加: 评分内核的工作量正比于窗口宽度, 而评分只占完整
流程的 3% 到 9%.

## 七. 世界尺寸

地形生成里有六个分段常量, 它们都来自世界生成的原式, 不是拍脑袋的数字:

- 特征重抽窗口: `floor(W * 0.45) + 1` 到 `ceil(W * 0.55) - 1`, 等价于 WorldGen 的
  `x > W * 0.45 && x < W * 0.55`. 中世界的 0.55W 双精度结果是 `3520.0000000000005`,
  所以 x = 3520 也要重抽, 写成闭区间时终点就是 3520.
- 强制平台窗口: 同法取 `floor(W * 0.48) + 1` 到 `ceil(W * 0.52) - 1`.
- 地表限制: `H * 0.17`, `H * 0.23`, `H * 0.26` 截断成整数, 分别是下限, 海滩段上限和内陆段上限.

三个世界尺寸上这些都是精确整数:

| 世界 | W x H | 重抽窗口 | 平台窗口 | 地表限制 |
| --- | --- | --- | --- | --- |
| 小 | 4200 x 1200 | 1891 到 2309 | 2017 到 2183 | 204 / 276 / 312 |
| 中 | 6400 x 1800 | 2881 到 3520 | 3073 到 3327 | 306 / 414 / 468 |
| 大 | 8400 x 2400 | 3781 到 4619 | 4033 到 4367 | 408 / 552 / 624 |

这张表在 `src/world-geometry.h`, `internal/task/model.go` 和 `web/gpu/terrain-reference.js` 各有一份,
Metal 内核通过参数数组接收, WGSL 通过 uniform 接收. 三份都要一起改, Go 与前端测试里各有一条钉住数值的用例.

中世界一行必须与旧实现逐位一致. 换世界尺寸时用 `--profile` 对拍过: 同一种子在 1000 列上, C++ 与 JS 参考实现
逐列相同, 修参数化之前的中世界剖面也与之后逐列相同.

顺带修掉一处旧分歧: WGSL 和 Metal 原来写的是 `x > 2880 && x < 3520`, 严格小于会漏掉 x = 3520 这一列,
而 CUDA 与 JS 参考按双精度语义包含它. 中世界的窗口止于 3400 列, 碰不到这一列, 所以从没暴露; 大世界的窗口
会跨过 3781 到 4619 这段, 必须统一, 现在四处都用闭区间 `[roll_lo, roll_hi]`.

**地表下限不是整数.** 小世界 1200 * 0.17 = 204.00000000000003, 大世界 2400 * 0.17 = 408.00000000000006,
而中世界 1800 * 0.17 = 306.0 恰好精确 (0.23 和 0.26 在三个尺寸上都精确). 这半个 1e-14 会改变行为:
地表正好停在整数那一格时, 双精度语义下 `surface < H * 0.17` 仍然成立, 于是再钳一次并把 `remaining`
归零, 后续随机数消耗随之改变; 整数实现若按严格小于比较, 就会漏掉这次钳制. 大世界 seed 42 在第 1560 列
就撞上了这处, 表现为整段地形分叉.

处理办法是把地表记成 `(整数格, 是否带下限的正偏移)`: 钳到下限时置上偏移, 之后比较下限含端点,
钳到海滩上限或内陆上限时清掉偏移. 中世界偏移恒为 0, 与旧实现逐位相同. 四个后端都按这套状态走,
全宽 4200 / 6400 / 8400 列在 seed 0, 42, 1069502010 上与 JS 参考逐列相同.

出生点跟着世界走: 世界中心加减 5 再留 64 列标注容差, 小世界 2031 到 2169, 中世界 3131 到 3269,
大世界 4131 到 4269. 模拟列数必须盖住出生点附近的窗口, 工作台换世界时会给出对应默认值 (2300 / 3400 / 4400).
