# terraria-seed-searcher

从游戏截图反推泰拉瑞亚世界种子的工具集与完整方法论.

> 泰拉版本: 1.4.5.8

## 结果

```
种子      (种子已隐去)
参数      中世界 / 猩红 / 专家
验证      仍需完整地形核对, 当前重新标注截图
```

搜索空间为 `[0, 2^31)`, 即 21.5 亿个种子; 在两张 RTX 4090 上约 40 分钟扫完.

## 问题建模

泰拉瑞亚的地图 ID 是一个 32 位有符号整数, 但负数会被取绝对值, 所以只需扫 `[0, 2^31)`.
世界生成由 `WorldGenerator` 的若干 pass 逐段推进, 每个 pass 进入时都会用
`UnifiedRandom` (.NET 的减法随机数发生器, 56 个 int 的内部状态) 重新播种.
因此给定种子, 出生点附近的地表高度是**完全确定**的, 这就是可以用来比对的特征.

## 方法概要

1. **取观测**. 用游戏主画面截图 (不是地图), 提取出生点附近逐格的地表高度.
2. **定标**. 求出每格的像素宽, 相位, 以及出生点在剖面里的列号. 这一步最容易出错, 见下文.
3. **判据**. 模拟剖面对齐后计算"逐格命中率" (残差不超过半格的列占比), 纵向偏移用残差中位数消掉.
4. **搜索**. GPU 双内核: 一个内核逐种子模拟并写出所需列的窗口, 另一个内核对窗口打分.
5. **验证**. 用已知种子造一份同格式观测, 跑同样的搜索, 确认真种子拿满分且假候选带足够低.

## 页面工作台

从 [Releases](https://github.com/azazo1/terraria-seed-searcher/releases) 下载对应平台的归档, 解压后直接运行 `terraria-seed-searcher` (Windows 为 `.exe`). 页面资源已经嵌入可执行文件, 不需要 Python.

源码运行时执行:

```shell
just serve
```

打开 <http://127.0.0.1:8791/>, 在左侧依次切换截图, 网格标定, 图片拼接, 标注, 搜索和候选.
编辑自动保存, 切换步骤时会先等待保存完成, 下一步直接读取最新进度.
保存失败时会留在当前步骤, 修改仍保留在页面中.

- 截图支持多选导入, 剪贴板粘贴, 拖放和删除.
- 网格标定使用 `左键拖动` 选第一条, `右键拖动` 选第二条, 松开鼠标确认. 左侧可修改两线间隔格数, 保持两端位置并重新计算格距. 普通拖动任意一端时另一端固定, `Ctrl + 拖动已选线` 则平移该方向的网格与两条线, 保持格距不变. Esc 取消当前拖动.
- 图片拼接继承每张图的网格, 可按缩放百分比, 显示宽度或高度等比调整单图大小, 也可匹配另一张可见图片的有效格宽. 左上角位置固定, 图片与网格一起缩放, 原图和原始标定不变. 支持图层选择, 锁定位置与大小, 位置微调, 撤销和重做.
- 标注吸附鼠标所在方块中心, 高亮 1 x 1 格, 支持拖动连续标注, 擦除, 撤销和重做, 刷新后恢复进度. 搜索使用的地表高度仍取方块上边缘.
- 标注页可调图片不透明度, 调到 0 时只剩标记和网格, 便于检查标注结果.
- 标注仅保留地表方块, 作废和擦除工具. 台阶化 (斜坡) 的格子也按地表方块标注, 不改变当前搜索的高度数据; 旧斜坡标记会自动转换, 作废列不参与搜索.
- 标注页仅在可见图片缩放后的格宽或格高最大值比最小值大超过 5% 时警示, 不阻止标注. 可返回图片拼接调整单图大小, 隐藏图片不参与比较.
- 在粗筛页的搜索准备卡片导出和导入最终观测 JSON: 仅包含以格为单位的逐列高度, 缺失或作废列 (-999) 和出生点观测列号. 无需截图匹配, 不包含截图, 标定, 拼接, 画布标记或搜索设置. 导入后直接用于搜索, 不会自动启动; 之后保存人工标注会重新生成观测.
- 滚轮缩放, 空格或中键拖动平移, `F` 适应图片. 拼接与标注页也支持右键平移. 拼接时方向键微调, `L` 切换锁定.

计算方式可在粗筛设置中手动选择:

| 方式 | 计算位置 | 准备 |
| --- | --- | --- |
| 主机 CPU | 运行工作台服务的主机, 多线程后台进程 | 发布包自带 `sweep-cpu`; 源码运行 `just build-cpu` |
| 主机 NVIDIA GPU (CUDA) | 运行工作台服务的主机 | 发布包自带 `sweep`; 源码运行 `just build` |
| 主机 Apple GPU (MLX/Metal) | 运行工作台服务的主机, 仅 macOS | `brew install mlx mlx-c`, 然后 `just build-mlx` |
| 浏览器 GPU (WebGPU) | 打开页面的设备 | 浏览器支持 WebGPU, 使用 localhost 或 HTTPS |

四个后端都支持小世界 (4200 x 1200), 中世界 (6400 x 1800) 和大世界 (8400 x 2400), 最多 700 个观测列且至少 20 个有效列. 世界尺寸是世界生成的分段边界决定的, 三张表在 Go, C++, Metal 和 WGSL 里各留一份并互相钉住, 换世界只需要选择尺寸. WebGPU 使用 WGSL 内核, 每次先对拍 12 个种子的完整地形和观测评分, 不一致就停止. 浏览器和 CPU 结果保留得分最高的前 2000 条, 已提交的浏览器候选也会保存在服务端. MLX 后端把同一套逐列生成和评分写成 Metal 内核算在 Apple GPU 上, 结果与 CPU 逐位一致, 同样保留前 2000 条.

搜索开销几乎全在地形逐列生成上: 实测生成占 91% 到 98%, 评分只占 2% 到 9%. 随机数的逐列消耗因此是唯一值得优化的部分. 原实现把每一列的三到四次随机数消耗都走了一遍双精度乘法和整型往返, 而 `Next(max)` 实际等于 `sample * max / 2147483647` 向下取整. 改成整数乘法和常数除法后逐位不变, 在消费级显卡上尤其明显, 因为这类显卡的双精度吞吐只有单精度的 1/64. 同机实测 100 万种子 CUDA 从 3.93 s 降到 1.09 s; 单线程 CPU 每秒种子数提高 1.6 倍, 8 线程时后四个线程落在能效核上, 整体只提高 1.39 倍. 另外地形只在观测窗口内被读取, 生成到窗口末尾即可停止, 不再继续推进到 `cols`. 第二轮把地表累加改成 1/8 格整数, 把 `Next(k) == 0` 的判断换成阈值比较, 并按 55 循环的可预知性预取下一步的随机数状态, CUDA 再降到 1.05 s 到 0.69 s (约 1.5 倍). 详见 [性能说明](docs/search-performance.md).

四种后端共用进度卡片, 显示扫描数量, 百分比, 平均速度, 已用时间, 预计剩余时间和累计候选. 主机状态每秒刷新, CPU 每秒报告进度, CUDA 和 MLX 每批结束后报告进度, 首批完成前显示正在估算. 搜索结束或停止后保留实际进度.

候选页在搜索过程中自动刷新. 网页新搜索会创建持久化任务, 候选和安全续跑位置在同一事务中保存. 停止时等待当前工作块完成, 刷新页面或重启服务后可在 "保存的搜索任务" 中手动继续. 恢复使用原任务的观测和参数, 新任务保留旧任务及其候选. WebGPU 失联后最多等待 30 秒即可恢复. 搜索器版本变化时需创建新任务. 工作块大小, 恢复边界和启动开销见 [断点恢复说明](docs/search-resume.md). 更新原生源码后需要重新运行 `just build-cpu` 或 `just build`, 才能使用原生运行中候选发布功能.

校准与标注不需要 GPU.
本地截图和编辑进度均已忽略, 不会作为源代码提交.

## 快速上手

Windows 和 Linux 发布包内的 `sweep` 是预编译 CUDA 搜索器, 静态链接 cudart, 只需要 NVIDIA 驱动, 不需要安装 CUDA Toolkit. Windows 包覆盖 Maxwell 到 Blackwell 的显卡, 更老的 Kepler 不在支持范围内. macOS 发布包只带 `sweep-cpu`, 需要 Apple GPU 时按上面的表格从源码构建 MLX 搜索器.

从源码构建时, Windows 使用能找到 `nvcc` 和 MSVC `cl` 的开发者终端, 输出为仓库根目录的 `sweep.exe`; Linux 输出为 `sweep`.

```shell
just build

# 单卡
./sweep data/observed_manual.txt --range 0 1073741824 \
    --tol 0.5 --offer 0.55 --batch 1000000 --device 0 \
    --marker 141 --cols 3400

# 多卡, 自动平分种子区间
./sweep data/observed_manual.txt --range 0 2147483647 \
    --tol 0.5 --offer 0.55 --batch 1000000 --device all \
    --marker 141 --cols 3400
```

工作台里的 GPU 编号填 `-1` 等价于 `--device all`.

参数含义:

| 参数 | 含义 |
| --- | --- |
| `--marker` | 出生点在观测剖面里的列号 |
| `--world` | 世界尺寸: `small`, `medium` (默认) 或 `large` |
| `--spawn-lo` / `--spawn-hi` | 出生点的世界列范围 (**不是**减去 marker 后的值). 不给时按世界规则推导 (中心加减 5, 再留 64 列标注容差) |
| `--cols` | 需要模拟到第几列 |
| `--tol` | 命中判据的容差, 单位格 |
| `--offer` | 只保留分数高于此值的种子 |
| `--device` | `0` 起始的 GPU 编号; `all` 或 `-1` 使用全部显卡 |
| `--batch` | 一次提交多少种子; 显存装不下时会自动缩小, 并在启动时打印实际值 |
| `--scales` | 逗号分隔的比例尺集合 |
